# agent-workflow

Процесс разработки фичи с агентом в Claude Code: от сырого ТЗ до закоммиченного тикета. Работает поверх скиллов [mattpocock/skills](https://github.com/mattpocock/skills) и добавляет к ним то, чего там нет: проверяемый разбор ТЗ, сверку PRD и тикетов с требованиями, строгий цикл реализации с остановками.

## Что внутри

| Скилл | Что делает |
|---|---|
| `/setup-workflow` | разворачивает процесс в проекте: `docs/agents/workflow.md` (пути и команды), блок процесса в `CLAUDE.md`, журнал проколов |
| `/intake` | первичный разбор материалов. Лёгкий режим: агент сам, с цитатами. Полный: два слепых аналитика, скрипт проверки цитат, судья, реестр требований `ТЗ-NNN`, до 10 вопросов пользователю |
| `/solution-design` | схема решения между грилем и PRD, ручная проверка |
| `/spec-check` | PRD против реестра требований в обе стороны: что выпало, что расходится, что в PRD без опоры |
| `/ticket-check` | тикеты против реестра и PRD: непокрытое, устаревшее, неполное |
| `/implement` | один тикет: объяснение задачи, швы и тесты с судьями, реализация, ручная приёмка, код-ревью, коммит |
| `/to-test-cases` | ручные тест-кейсы для тестировщика, по экранам флоу |

Размеры задачи S / M / L решают, какие шаги нужны: на мелочи полный процесс не гоняется. Таблица - в [skills/setup-workflow/templates/CLAUDE-block.md](skills/setup-workflow/templates/CLAUDE-block.md).

## Установка

Один раз на машину:

```sh
git clone https://github.com/svgerasimov/agent-workflow.git ~/dev/agent-workflow
~/dev/agent-workflow/install.sh
```

Глобально ставится только `/setup-workflow`, остальные скиллы лежат у него внутри архивом. Почему не все глобально: личные скиллы перекрывают проектные с тем же именем, и если в каком-то проекте свой `/intake` или `/implement`, он перестанет работать.

Обновиться: `git pull` в `~/dev/agent-workflow`, снова `install.sh`, потом `/setup-workflow` в проекте.

Скрипт подскажет, каких скиллов Покока не хватает, и даст команды для установки. `install.sh --rules` - ещё и личные правила общения в `~/.claude/rules`.

## Запуск в проекте

1. В корне проекта запустить `claude`.
2. Внутри Claude: `/setup-workflow`. Распакует скиллы в `.claude/skills`, напишет настройки `docs/agents/workflow.md` и блок процесса в `CLAUDE.local.md`. Всё это прячется через локальный `.git/info/exclude`: в коммиты и в репозиторий проекта ничего не попадает.
3. Перезапустить `claude` (новые скиллы подхватываются в новой сессии), кинуть материалы фичи и написать `/intake`.

## Требования

Claude Code, Node 18+ (скрипты `/intake`), для PDF - macOS (`swift`) или `pdftotext` из poppler.
