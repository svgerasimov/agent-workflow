# Skill: развернуть процесс в проекте

Запускать один раз на проект, в его корне. Ничего из процесса не попадает в git проекта: всё прячется через локальный `.git/info/exclude`. Повторный запуск обновляет блок в CLAUDE.md и дописывает в `workflow.md` недостающее, не затирая заполненное.

Все ответы - на языке пользователя, коротко.

## 0. Распаковать скиллы

`/setup-workflow` стоит глобально, а остальные скиллы процесса (`intake`, `spec-check`, `ticket-check`, `implement`, `solution-design`, `to-test-cases`) лежат архивом в папке этого скилла: `<папка скилла>/bundle.tar.gz`. Глобально их не ставим: личные скиллы перекрывают проектные с тем же именем.

1. Проверить `.claude/skills/` проекта. Скилл с тем же именем уже есть и это не наша прошлая распаковка (нет строки в `.claude/skills/.agent-workflow`) - не трогать, сказать пользователю и спросить.
2. Распаковать: `tar -xzf <папка скилла>/bundle.tar.gz -C .claude/skills/`. Записать в `.claude/skills/.agent-workflow` список распакованных скиллов и версию из `<папка скилла>/bundle.version`. Повторный запуск - перезаписать только скиллы из этого списка.
3. Спрятать от git: дописать в `.git/info/exclude` (локальный, не коммитится) строку `.claude/skills/<имя>/` по каждому скиллу и `.claude/skills/.agent-workflow`. Не в `.gitignore`: он коммитится и попадёт в репозиторий.
4. Проверить `git status --short`: распакованного там быть не должно.

Скиллы подхватятся в следующей сессии Claude Code. В этой продолжать по шагам ниже, читая файлы скиллов напрямую, если понадобятся.

## 1. Посмотреть проект

Прочитать, что есть: `CLAUDE.md`, `AGENTS.md`, `README`, манифесты (`package.json`, `pyproject.toml`, `Makefile`, `go.mod`, `build.gradle`, `Cargo.toml` и т.п.), конфиги тестов и линтера, `.git/info/exclude`, последние коммиты (`git log --oneline -15`) - по ним видно формат сообщений и веток.

Из этого заполнить черновик [templates/workflow.md](templates/workflow.md): команды тестов, типов, линтера, запуска, формат коммитов, стек тестов. Чего не видно из файлов - оставить `<...>`.

## 2. Спросить недостающее → ⛔ СТОП

По одному вопросу за сообщение, только то, чего нет в файлах и без чего скиллы не работают:
- формат номера тикета и ветки (если не видно по `git log`);
- команда запуска приложения для ручной приёмки, если её нет в манифестах.

Остальные `<...>` можно оставить - скиллы спросят по ходу.

## 3. Записать

- `docs/agents/workflow.md` - из черновика. Файл уже есть - дописать только пустые разделы.
- Блок процесса [templates/CLAUDE-block.md](templates/CLAUDE-block.md) - в `CLAUDE.local.md` в корне проекта (Claude Code читает его вместе с CLAUDE.md, но это личный файл, не общий для команды). Блок между `<!-- agent-workflow:start -->` и `<!-- agent-workflow:end -->` уже есть - заменить его целиком, остальной файл не трогать. Общий `CLAUDE.md` и `AGENTS.md` не трогать: они в репозитории, их читают коллеги.
- `docs/agents/incidents.md` - если нет:

  ```markdown
  # Журнал проколов

  Где агент неверно понял ТЗ или потерял требование, и почему. Каждая строка - эвал-кейс для /intake.

  | # | Дата | Фича | Что пропустили или поняли неверно | На каком шаге заметили | Кейс |
  |---|---|---|---|---|---|
  ```
- **Всё агентское - вне git** по умолчанию: дописать в `.git/info/exclude` строки `CLAUDE.local.md`, `docs/agents/`, папку фич из `workflow.md` (по умолчанию `context/`). Если какой-то из этих путей уже отслеживается git (`git ls-files <путь>`) - не прятать, сказать пользователю. Пользователь прямо попросил класть процесс в git - тогда не прятать ничего, а блок писать в `CLAUDE.md`.
- В конце `git status --short`: из записанного там не должно быть ничего.

## 4. Проверить зависимости

Процесс опирается на скиллы Покока: `grill-with-docs` (или `grilling` + `domain-modeling`), `to-spec`, `to-tickets`, `tdd`, `code-review`, `codebase-design`, `to-questionnaire`, `wait-what`. Проверить, есть ли они в `~/.claude/skills/` или `.claude/skills/`. Нет - дать пользователю команду (сам не ставить):

```
npx -y skills add mattpocock/skills -g -y -a claude-code -s <имя>
```

по одному `-s` на скилл.

Проверить `node -v` (скрипты `/intake` на Node 18+) и инструмент для PDF: на macOS `swift`, иначе `pdftotext`.

## 5. Итог

Одним сообщением: что записано, что осталось `<...>` в `workflow.md`, каких скиллов не хватает. И как начать: "кинь материалы фичи и напиши `/intake`".
