# Эвалы /intake

Набор реальных проколов: на каждом ТЗ разбор обязан найти то, что когда-то пропустили. Меняешь скилл (промпты аналитиков, судью, модели) - прогоняешь все кейсы и сравниваешь счёт. Новый прокол из журнала проколов проекта - новый кейс в тот же день.

Кейсы и прогоны лежат здесь же, в `cases/` и `runs/`, но в git не попадают (`.gitignore` репозитория): в них ТЗ с внутренними данными. Таблицы кейсов и прогонов - в `LOG.md` рядом, тоже вне git. Этот файл - только формат.

## Кейс

`cases/<NNN>-<slug>/`:
- `case.md` - что в ТЗ (с цитатами и страницами), что сделал агент, почему пропустили, что разбор обязан поймать (`M1`, `M2`, …) и чего быть не должно (`N1`, …);
- `expected.json` - то же для скрипта:

```json
{
  "source_dir": "<папка фич>/<feature>/source",
  "must_find": [
    { "id": "M1", "in": ["registry", "conflicts"], "pages": [30, 38], "regex": "формирует.*JSON|JSON.*формирует" }
  ],
  "must_not": [
    { "id": "N1", "in": ["registry"], "regex": "бэк сам формирует" }
  ]
}
```

`in` - разделы `judge.json`, где искать; `pages` - страницы источника, хотя бы одна должна совпасть; `regex` - по `statement`, `note`, `what`, `why_it_matters`, `readings` и цитатам.

## Прогон

`/intake eval <NNN>`, потом:

```
node <папка скилла intake>/scripts/check-eval.mjs runs/<дата>-<NNN>/judge.json cases/<NNN>-<slug>/expected.json
```

Результат - строкой в таблицу "Прогоны" в `LOG.md`: дата, что меняли в скилле, счёт по кейсам, цитаты ok / всего из `quote-check.json`, время и токены.
