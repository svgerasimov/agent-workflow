# Эвалы /spec-check

Реальные проколы сверки: на каждом кейсе судья обязан поднять то, что когда-то пропустили. Меняешь скилл (промпт судьи, модель, нарезку диапазонов) - прогоняешь все кейсы и сравниваешь счёт. Новый прокол сверки из журнала проколов проекта - новый кейс.

Кейсы и прогоны лежат здесь же, в `cases/` и `runs/`, но в git не попадают (`.gitignore` репозитория): в них ТЗ и PRD с внутренними данными. Таблицы кейсов и прогонов - в `LOG.md` рядом, тоже вне git. Этот файл - только формат. Папка - в клоне репозитория (`workflow.md` проекта, по умолчанию `~/dev/agent-workflow`); прогонять скилл из клона, а не установленную копию: проверяется та версия, которую правим.

## Кейс

`cases/<NNN>-<slug>/`:
- `case.md` - что в ТЗ (с цитатами), что было в PRD, почему пропустили, что сверка обязана поймать (`M1`, …) и чего быть не должно (`N1`, …);
- `source/` - текст ТЗ (`.txt`), `prd.md`, `requirements.md` - снимки в том виде, в каком сверка их пропустила: живые файлы фичи после исправления уже не годятся. В снимке реестра колонка "Где в PRD" пустая: её заполняет сам судья;
- `expected.json` - пути к входу (относительно папки кейса), диапазон реестра для судьи, `must_find` и `must_not`:

```json
{
  "case": "001-<slug>",
  "source": "source/<file>.txt",
  "prd": "prd.md",
  "registry": "requirements.md",
  "range": "ТЗ-072…ТЗ-176",
  "must_find": [
    { "id": "M1", "in": ["trace"], "ids": ["ТЗ-111"], "status": ["расходится"], "regex": "..." }
  ],
  "must_not": [
    { "id": "N1", "in": ["unsupported"], "regex": "..." }
  ]
}
```

`in` - разделы `judge.json` (`trace`, `unsupported`); для `trace` можно сузить по `ids` и `status`; `regex` - по тексту записи (`claim`, `note`, `prd`, `detail`, `what_happens`, `prd_says`, `risk`, цитаты).

**Диапазон - боевой**, тот, что был у судьи, который пропустил. На узком куске вокруг нужного места судья читает внимательнее и находит то, что на боевом диапазоне пропускает: кейс зеленеет без всякой правки и ничего не проверяет.

## Прогон

`/spec-check eval <NNN>` - один судья из шага 2 (режим реестра) на входе кейса, обратный проход (PRD → реестр) включён, хотя диапазон не первый. Без показа находок пользователю и без записи в папку фичи.

Судье - **копии** входа в нейтральной папке (`source/tz.txt`, `prd.md`, `requirements.md`), не пути к кейсу: в имени кейса и в `case.md` рядом написано, что ищем. В промпт - "работай только с перечисленными файлами".

Потом:

```
node <папка скилла spec-check>/scripts/check-eval.mjs runs/<дата>-<NNN>/judge.json cases/<NNN>-<slug>/expected.json
node <папка скилла intake>/scripts/check-quotes.mjs <копия source> runs/<дата>-<NNN>/judge.json > runs/<дата>-<NNN>/quote-check.json
```

Порядок правки промпта:
1. Новый кейс сначала прогнать на текущем промпте: он должен быть красным. Зелёный - кейс не воспроизводит прокол, делать строже (чаще всего - вернуть боевой диапазон).
2. Правка → прогнать все кейсы, не только новый.
3. Судья отвечает по-разному от раза к разу: кейс, который просел после правки, прогнать ещё 2 раза, прежде чем винить правку.

Результат - строкой в "Прогоны" в `LOG.md`: дата, версия скилла и что меняли, счёт по кейсам, цитаты ok / всего, время и токены.
