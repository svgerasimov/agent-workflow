# Эвалы /ticket-check

Реальные проколы перепроверки тикетов: на каждом кейсе судья обязан поднять то, что когда-то пропустили. Меняешь скилл (промпт судьи, модель, нарезку диапазонов) - прогоняешь все кейсы и сравниваешь счёт. Новый прокол из журнала проколов проекта, где тикет разошёлся с PRD или реестром, - новый кейс.

Кейсы и прогоны лежат здесь же, в `cases/` и `runs/`, но в git не попадают (`.gitignore` репозитория): в них ТЗ, PRD и тикеты с внутренними данными. Таблицы кейсов и прогонов - в `LOG.md` рядом, тоже вне git. Этот файл - только формат. Папка - в клоне репозитория (`workflow.md` проекта, по умолчанию `~/dev/agent-workflow`); прогонять скилл из клона, а не установленную копию: проверяется та версия, которую правим.

## Кейс

`cases/<NNN>-<slug>/`:
- `case.md` - что в ТЗ (с цитатами), что было в PRD и тикете, почему пропустили, что проверка обязана поймать;
- `source/`, `prd.md`, `requirements.md`, `tickets/` (открытые в корне, закрытые в `done/`) - снимки в том виде, в каком тикет разошёлся;
- `expected.json` - пути к входу (относительно папки кейса), диапазон реестра для судьи, `must_find` (раздел `ticket_findings` / `uncovered` / `coverage`; для `ticket_findings` - `tickets` и `kind`, для остальных - `ids`; regex по тексту) и `must_not`.

Диапазон - боевой, тот, что был бы у судьи на настоящей проверке.

## Прогон

`/ticket-check eval <NNN>` - один судья из шага 1 на входе кейса. Без показа находок пользователю и без записи в папку фичи. Судье - копии входа в нейтральной папке, не пути к кейсу: в имени кейса и в `case.md` написано, что ищем.

```
node <папка скилла ticket-check>/scripts/check-eval.mjs runs/<дата>-<NNN>/judge.json cases/<NNN>-<slug>/expected.json
```

Новый кейс сначала прогнать на текущем промпте: должен быть красным. Зелёный - кейс не воспроизводит прокол, или промпт ловит и пропуск был в том, что проверку не запускали; тогда кейс остаётся как защита от поломки.

Результат - строкой в "Прогоны" в `LOG.md`: дата, версия скилла и что меняли, счёт, цитаты ok / всего.
