# Изменения

Версия - в [VERSION](VERSION), у каждой версии git-тег `v<версия>`. Какая стоит в проекте - в `.claude/skills/.agent-workflow` (после `/setup-workflow`) или `.claude/skills/.agent-workflow-version` (после `install.sh <проект>`).

Правка промпта скилла выходит новой версией только после прогона всех эвал-кейсов этого скилла (`skills/<скилл>/evals/`); счёт - в строке версии.

## 0.2.0 - 03.11.2026

`/spec-check` - три правила для судьи, каждое под реальный пропуск сверки:
- PRD применяет правило ТЗ к большему кругу (ТЗ называет один вид, роль или поле, PRD - ещё другие) - "расходится", даже если сам случай из ТЗ в PRD есть. В обратном проходе проверяются и допущения `Д-N`: расширение правила ТЗ - в `unsupported` с пометкой "расширение Д-N".
- Формулировка PRD читается двояко и одно прочтение расходится с ТЗ - "расходится", а не "есть", даже если судья сам нашёл верное прочтение. Пример из ТЗ прогоняется через формулировку PRD.
- У ключа тела запроса сверяется не только наличие, но и значение: подкреплено, только если ТЗ говорит, откуда его брать или как считать. Совпадение с примером - не опора.

Эвалы: 3 кейса, на боевых диапазонах - 4/4, 2/2, 2/2 (001 и 003 - по два прогона).

`/spec-check`, `/ticket-check` - режим `eval <NNN>`, скрипты счёта `scripts/check-eval.mjs`, формат кейсов в `evals/README.md`.

Эвалы всех скиллов - в клоне репозитория, вне git (`.gitignore`): кейсы с внутренними ТЗ в GitHub и в проекты не уходят, `install.sh` их не копирует и не кладёт в архив.

Версия: файл `VERSION`, этот журнал; `install.sh` пишет номер версии в `bundle.version`.
